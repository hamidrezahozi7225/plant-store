# TypeScript and Zod Setup Design

## Goal

Convert the existing Express project into a minimal TypeScript application and add Zod for runtime input validation. Existing runtime dependencies remain unchanged.

## Tooling

- `typescript` compiles source files and performs static type checking.
- `tsx` runs TypeScript directly during development and restarts the server when files change.
- `@types/node` and `@types/express` provide Node.js and Express type definitions.
- `zod` is a production dependency because request validation runs in the deployed application.

## Project Structure

```text
plantStore/
├── src/
│   └── index.ts
├── dist/                  # generated by the TypeScript compiler
├── package.json
└── tsconfig.json
```

The initial `src/index.ts` will contain a small Express server, a health endpoint, and one POST endpoint demonstrating request-body validation with Zod. This keeps the starter understandable without adding authentication, database models, or domain features.

## Runtime Flow

1. Express receives a request.
2. The POST endpoint calls `schema.safeParse(req.body)`.
3. Valid input produces a success response containing typed data.
4. Invalid input produces HTTP 400 with Zod's structured validation issues.
5. Express listens on `process.env.PORT`, falling back to port 3000.

## Scripts

- `npm run dev` starts the server with `tsx` in watch mode.
- `npm run typecheck` checks types without creating output.
- `npm run build` compiles `src` into `dist`.
- `npm start` runs the compiled JavaScript.

## Compiler Configuration

TypeScript will use strict checking, Node-compatible module resolution, `src` as `rootDir`, and `dist` as `outDir`. Generated JavaScript and source maps will not be committed as source.

## Error Handling

Zod validation failures return status 400 and a JSON object containing a short message and validation issues. Unexpected errors are left to Express's standard error behavior in this minimal starter; centralized error middleware can be introduced when the application gains real routes.

## Verification

The setup is complete when dependencies install successfully, `npm run typecheck` passes, `npm run build` produces runnable JavaScript, and quick HTTP checks confirm that valid input succeeds while invalid input returns HTTP 400.

## Out of Scope

- Authentication and authorization
- Mongoose models or database connectivity
- Plant/product CRUD features
- A larger route/controller/service architecture
- Automated test-framework setup
